# SILENT BLADE v0.8 — MISSION 01: THE SHADOW OF THE VILLAGE

## Intent

Deliver the first complete playable mission as a vertical slice on top of the v0.7 codebase. The mission demonstrates platforming, grapple traversal, combat, stealth, enemy perception, distractions, alarm handling, contextual interaction, objective progression, checkpoint recovery and end-of-mission evaluation in one connected level.

## Mission flow

1. **Briefing / infiltration:** Рэн enters the outer perimeter. The first tutorial hint appears on mission start; grass and dark pockets teach reduced exposure.
2. **Residential quarter:** street patrols and a roof route lead through houses and lantern-lit areas. `hidden_cache` and `field_report` are optional discoveries.
3. **Guarded courtyard:** the player encounters Guard, Scout and Heavy Guard patrols, the watchtower, a signal console and a passage locked behind `signal_disabled`.
4. **Archive:** the archive's side door and upper route provide alternate access. `archive_orders` is the required mission document. The archive objective can be completed before or after the signal objective.
5. **Evacuation:** the exit is unavailable until both `orders_collected` and `signal_disabled` are true. Interacting with the exit completes the final objective and presents results.

World width is 6,200 px. Zone boundaries are declared in `data/missions/mission_01.json`: A 0–1,000; B 1,000–2,250; C 2,250–3,650; D 3,650–4,650; E 4,650–6,200. The level builder supplies a ground approach, staggered roof platforms, stepping platforms, a guarded courtyard, archive access and an elevated evacuation route. Grapple anchors span the level.

## Mission data and progression

`data/missions/mission_01.json` is the authored mission configuration. It defines story text, spawn, zone descriptions, eight enemy spawn descriptors, objectives, optional tasks, two secrets, checkpoints and tutorial trigger data.

`MissionManager` loads that data and owns the run state. `ObjectiveManager` uses a prerequisite graph rather than only a fixed step index:

- `enter_village` has no prerequisite.
- `disable_signal` requires `enter_village`.
- `retrieve_orders` requires `enter_village`, so document and alarm can be handled in either order.
- `evacuate` requires both `disable_signal` and `retrieve_orders`.

Unique item IDs reject duplicate pickups. Optional tasks are independent from the main path: no detections, no neutralizations, all secrets and both documents. They never block extraction.

## Interactions

`MissionInteractable` is the shared physical interaction object. Doors create a solid `StaticBody2D` barrier which is disabled only when the door is opened. One-shot items become consumed after successful interaction. Locked objects expose a prompt and reject use until their world flag is set.

`InteractionSystem` registers the level's interactables, selects the nearest available object inside its interaction range, updates the contextual hint and tells `TouchControls` to display the `ДЕЙСТВИЕ` button. Touch ownership remains per finger; the action is not a decorative HUD button.

Successful interactions call the existing player noise API with per-object radius/intensity. A heavy door/alarm console is louder than a document or checkpoint. Noise only identifies the interaction point, not a continuously updated player position.

## Alarm and existing AI

`AlarmSystem` exposes CALM, LOCAL_ALERT and GLOBAL_ALARM. A guard's existing v0.7 `player_spotted` signal can raise local suspicion; in the guarded courtyard it also raises global alarm while the device is active. Global alarm publishes one high-radius event at the fixed signal-device position through the already existing `NoiseSystem`. Existing enemy noise listeners move guards into the alert/investigation/search cycle. The console disables the source; it does not replace vision, hearing or enemy FSM logic.

## Checkpoint semantics

`CheckpointSystem` stores checkpoint ID, respawn coordinates, whether the signal device was still enabled and a deep copy of mission progress. On player death, the active mission manager is deliberately not rewound: elapsed time, detections, alarms, collected IDs, flags and objectives remain in the current run. The level reconciles consumed objects and open doors from those IDs/flags, restores alarm state, resets the player and recreates the configured enemies. This avoids duplicated documents/secrets and avoids resetting the player's earned mission progress. These are session checkpoints; there is no disk save/resume slot.

## Tutorial

The briefing screen has a persistent tutorial toggle stored in `user://silent_blade_settings.cfg`. Hints are short and tied to zone progress. The current hint can be dismissed immediately when the associated action is performed; it also has a short timeout so it cannot remain stuck indefinitely.

## Atmosphere and audio

The scene keeps Godot's lightweight GL Compatibility renderer. The level builder draws the moon and distant village through two parallax layers, houses, lanterns, bamboo, a watchtower and an archive facade. Roofs/steps/doors/cover are physical bodies, not only painted scenery. Fog bands and falling leaves are lightweight procedural effects. Six original WAV assets are included: looped 10-second ambience, wood step, grass step, interaction, document pickup and alarm signal. Audio hooks are attached to player noise events and mission interaction/alarm callbacks.

## Results and grade rules

The results screen shows time, detection count, alarm count, secrets, documents, neutralized enemies and all optional challenges, plus retry/continue/menu actions.

- **S:** ≤ 07:00; zero detections; zero alarms; all secrets; no neutralizations.
- **A:** ≤ 11:00; zero detections; no more than one alarm; at least one secret.
- **B:** ≤ 16:00; no more than two detections and two alarms.
- **C:** successful extraction that does not meet S/A/B.
- **D:** mission failure.

Optional challenges are shown separately from the grade and do not block extraction: no detection (`ghost_run`), no neutralizations (`no_kills`), both secrets (`all_secrets`) and both documents (`all_documents`). Scripted mission failure is routed through `_fail_mission(reason)` to the D-grade results screen; ordinary death remains checkpoint recovery.

## Android and performance

The project keeps 1280×720 landscape and GL Compatibility. `window/stretch/aspect="expand"` allows wider aspect ratios without vertically cropping the authored UI. Briefing, pause, results and campaign transition panels center against the actual viewport size for 16:9 and 19.5:9 layouts. The context action is only inserted into the touch layout when an object is available. Existing raw multi-touch routing is preserved, including cancellation and focus-loss release. The level uses a modest fixed enemy count (eight), 18 leaf particles, a few dozen area zones and interval-based AI vision from v0.7; it does not add per-frame raycasts for every object.
