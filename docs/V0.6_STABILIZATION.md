# SILENT BLADE v0.6 — stabilization report

Scope: audit, multitouch, startup/physics bugs, Android build pipeline. No new game systems, no new levels.

## 1. Problems found

| # | Where | Problem | Severity |
|---|---|---|---|
| 1 | `main.gd` | `player.add_child()` runs `player._ready()`, which emits `guard_changed` **before the HUD exists** → `_on_guard_changed` wrote to `guard_bar == null` (script error at every start) | high |
| 2 | world | No fall limit: the pit between the two ground platforms (x≈1470–1880) and knockback off a ledge meant falling forever; the camera stops at y=720 so the player just vanished | high |
| 3 | `player.gd` | After walking off a ledge and the 0.12 s coyote window, `jump_count` stayed 0 and no jump condition matched → no jump at all, not even the air jump | medium |
| 4 | `project.godot` | `textures/vram_compression/import_etc2_astc` was off — Godot refuses to export an Android build without it | high (build) |
| 5 | repo | No `export_presets.cfg`, no APK workflow in the archive | high (build) |
| 6 | `main.gd` | `_setup_input()` added key events again after every `reload_current_scene()` (restart / replay) → duplicated events accumulate | low |
| 7 | `enemy.gd` | local variable `visible` shadows `CanvasItem.visible` (parser warning, easy to misuse) | low |
| 8 | `touch_controls.gd` | the mouse fallback (`not is_touchscreen_available()`) could turn an emulated mouse event into an extra "finger" on devices where touch detection is wrong | low |
| 9 | docs | `AUDIT_AND_MULTITOUCH_FIX.md` (v0.5.1) described a fix that was not in the code — corrected in v0.5.2 | process |
| 10 | CI | `godot-validation.yml` did not fail on script errors (it only `tee`d the log) | medium |

Re-audited `touch_controls.gd`: finger → owner routing, per-finger release, tap preservation (`_pending_release`), focus loss, pause/results gating all hold up on reading. Button circles never overlap; the tightest gap between two buttons is ~14 design px (≈ 1280×720 space). Stick zone (left 46%) never intersects a button.

**Known, not changed in 0.6 (would be new systems):** enemies still see through walls (no line-of-sight ray); no SEARCH/RETURN states; player collides with enemy bodies but not vice versa (`collision_mask = 3` vs enemy `1`); layout assumes 16:9 (`aspect=keep`, letterboxed on taller/wider phones).
