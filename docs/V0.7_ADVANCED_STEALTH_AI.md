# SILENT BLADE v0.7 — Advanced Stealth & Enemy AI

## Scope

This update extends the supplied v0.6 project. It does not replace the player controller, combat, campaign flow, camera, HUD, touch router or export preset. New systems are attached to the existing runtime-spawned world and enemy instances.

## Architecture

```text
Player (player.gd)
  ├─ noise_emitted(position, radius, intensity, type, source_id)
  │      ↓
  │   main.gd → NoiseSystem (noise_system.gd)
  │                 └─ noise_emitted(event)
  │                       ↓
  │                  every Enemy.on_noise_event(event)
  └─ crouch / velocity ───────→ StealthSystem
                                  ├─ CoverSystem
                                  └─ StealthZone Area2D instances

Enemy (enemy.gd)
  ├─ EnemyAI: transition table / FSM gate
  ├─ VisionSystem: range + FOV + physics ray query
  └─ DetectionSystem: gradual fill, suspicious state, decay
```

The enemy script owns the high-level state because movement, attack timing, damage and reaction already lived there. The reusable perception, detection and state-transition rules are separate RefCounted modules. Noise, zones and decoys are independent Nodes. `main.gd` creates and wires the world instances, leaving player/combat state ownership unchanged.

### New modules

| File | Responsibility |
|---|---|
| `scripts/ai/enemy_ai.gd` | Allowed FSM states and transition table |
| `scripts/ai/vision_system.gd` | Range, facing/FOV and occlusion ray query |
| `scripts/ai/detection_system.gd` | Suspicion meter and HIDDEN/SUSPICIOUS/DETECTED stages |
| `scripts/stealth/noise_system.gd` | Shared event bus, short-lived event queue and visual sound ping |
| `scripts/stealth/stealth_zone.gd` | GRASS/COVER/DARK/LIGHT Area2D volumes and procedural visuals |
| `scripts/stealth/cover_system.gd` | Concealment from overlapping physical/grass cover volumes |
| `scripts/stealth/stealth_system.gd` | Combines crouch, speed, cover and lighting into exposure |
| `scripts/stealth/noise_decoy.gd` | Physics-driven thrown distraction and impact event |

## Enemy FSM and transitions

| State | Entry | Behavior | Exit |
|---|---|---|---|
| PATROL | Spawn or completed return | Moves between `left_limit` and `right_limit` | Visual suspicion or a heard event → ALERT; full detection → CHASE |
| ALERT | First sighting/suspicious noise | Stops, faces the event/last visual position, waits profile reaction delay | Full detection → CHASE; timer → INVESTIGATE |
| INVESTIGATE | Reaction timer elapsed | Moves toward the stored visual/noise event location | Within 26 px of the horizontal destination → SEARCH; new full visual detection → CHASE |
| CHASE | Detection meter reaches 1 | Tracks visible player; after LOS loss uses last known visual position | No LOS for 0.82 s → SEARCH; close visible target → ATTACK |
| ATTACK | Target in range, vertical tolerance and visible forward arc | TELEGRAPH → EXECUTE → RECOVERY phases | After recovery, CHASE if still detected, otherwise SEARCH; parry → STAGGER |
| SEARCH | Investigation/chase target lost | Sweeps around a fixed search center within profile radius | Search timer expires → RETURN; renewed detection → CHASE |
| RETURN | Search unsuccessful | Returns to the original patrol X coordinate | Reaches home point → PATROL; new suspicion → ALERT |
| STAGGER/KNOCKBACK | Parry or combat hit | Existing combat interruption and knockback behavior | Resume CHASE/SEARCH/PATROL depending on current knowledge |

Repeated footsteps while already ALERT do not restart the reaction delay. While INVESTIGATE is active, new valid noise can update the destination without restarting ALERT. Noise never overwrites `last_known_player_position`; that position is updated only by direct visual observation.

## Vision and detection

Vision is sampled at a profile-specific interval rather than every rendered frame:

- Guard: every 0.14 s, 430 px range, 82° field of view.
- Scout: every 0.10 s, 520 px range, 108° field of view.
- Heavy Guard: every 0.18 s, 370 px range, 72° field of view.

The direction vector is derived from the enemy's current facing. A PhysicsRayQuery2D runs on collision layer 1 from the enemy eye offset to the player's upper-body offset. The player is visible only if it is the first body hit. Platforms and physical cover crates on layer 1 block the ray. Areas are excluded from the ray query.

Detection increases with time, profile detection rate and current exposure. It decays at 0.30 units/s while not visible. Stages are HIDDEN (<0.10), SUSPICIOUS (0.10–0.998) and DETECTED (≥0.999). The UI shows the greatest active meter among enemies.

## Hearing and noise

Every event is a dictionary with:

- `position`: fixed event origin in world coordinates;
- `radius`: propagation distance in world pixels;
- `intensity`: normalized 0–1 strength;
- `event_type`: source category;
- `source_id`: emitter instance ID;
- `id` and `age`: event queue bookkeeping.

Enemies calculate distance falloff and multiply it by their individual hearing sensitivity. The noise manager emits the event synchronously to listeners, retains at most 24 events, and prunes events after 4.5 s. The sound ring is drawn for 0.72 s.

| Source | Radius / intensity |
|---|---|
| Running footstep | 170–240 px / 0.32–0.48, every 0.42 s |
| Crouched sneak step | 92 px / 0.16, every 0.72 s |
| First jump | 205 px / 0.48 |
| Double jump | 230 px / 0.58 |
| Landing | clamped 150–390 px, impact-scaled; `LAND` |
| Hard fall landing (impact ≥450 px/s) | same impact-scaled model; `FALL` |
| Dash | 340 px / 0.90 |
| Katana | 220 px / 0.66; finisher 280 px / 0.82 |
| Grapple attach | 145 px / 0.30 |
| Thrown decoy impact | 480 px / 0.95 |
| Object interaction API | defaults 190 px / 0.55 via `notify_interaction_noise()` |

The decoy is a CharacterBody2D with gravity and a small collision shape. It emits when it hits geometry or its fuse expires. Its event location is its impact point; the enemy does not receive the player's transform through this event.

## Stealth, cover and light

The player exposure starts from a stance/speed multiplier, then combines overlapping zones:

- Crouch: 0.68 base exposure.
- Speed above 240 px/s: ×1.18; speed below 55 px/s: ×0.90.
- Grass: ×0.36 crouching, ×0.72 standing.
- Physical cover area: ×0.54 crouching, ×0.78 standing.
- Dark zone: ×0.62.
- Light zone: ×1.20.

Final exposure is clamped to 0.18–1.35; even ideal cover is not absolute invisibility. Two wooden cover objects are actual StaticBody2D collision geometry on layer 1, so they block both movement and visual rays. Grass and light/dark areas are light-weight Area2D gameplay zones with procedural indicators.

Current environment zones:

- Grass: `(420,596)`, `(610,356)`, `(1810,466)`.
- Dark: `(1190,586)`, `(2240,582)`.
- Light: `(370,548)`, `(1580,348)`, `(1980,560)`.
- Physical cover: `(1120,587)` and `(1910,450)`, both with matching COVER areas.

## Android and HUD

The existing raw `InputEventScreenTouch` router remains the owner of per-finger actions. A `ШУМ` distraction button was added without replacing the joystick or existing buttons. `touch.canceled`, application focus loss, application pause, visibility loss and scene disabling pass through the existing release path. The new action is added to the same per-finger map as attack/jump/dash/grapple/block.

HUD adds a single aggregate detection meter, player concealment status and a priority-aggregated enemy state label. This avoids one idle enemy's PATROL signal hiding another enemy's active SEARCH/CHASE state. Each enemy also shows its own state dot and suspicion meter.

## Performance choices

- Vision query frequency is 5.5–10 Hz per enemy, profile-specific.
- Zone overlaps are evaluated when vision is sampled, not at frame rate.
- Noise queue is capped at 24 events and pruned every 0.5 s.
- Noise visualization is active only during the 0.72 s ping window.
- Lighting is represented by simple zone multipliers and procedural shapes; no per-pixel lighting/shadows are introduced.

## Known limitations

1. Enemy locomotion is horizontal, based on the existing patrol platform. There is no NavigationServer route planning or automatic jumping between platforms/vertical levels.
2. Sound is radius/intensity based and currently passes through walls; the event location is fixed, but acoustic occlusion is not implemented.
3. Darkness/light zones are gameplay exposure volumes, not dynamic `Light2D` shadows. Visuals are simple overlays to preserve Android performance.
4. Object interactions can call `notify_interaction_noise()`, but this update does not add a separate inventory or interaction quest system.
5. FOV, physics ray, Area2D overlap, actual touch delivery and runtime balancing still require Godot 4.3 and physical Android validation.
