# SILENT BLADE v0.4 — Combat update

## Controls

| Action | Keyboard | Android touch |
|---|---|---|
| Move | A / D or arrows | Virtual joystick |
| Jump | Space / W / Up | ПРЫЖОК |
| Attack | J / Z | УДАР |
| Block / parry | Hold K / X | Hold БЛОК |
| Crouch | S / Down | ↓ |
| Dash | Shift | РЫВОК |
| Grapple | E | КРЮК |
| Pause | Escape | Ⅱ |

Block is hold-based. The first 0.18 seconds after pressing block are the parry window. If an enemy's attack connects from the direction the player faces during that window, the attack is interrupted and the enemy enters stagger, creating a 1.1-second counter opportunity. The first attack started in that window deals 50% bonus damage. If the parry window expires, holding the button continues ordinary block.

Ordinary block spends 34 guard points per blocked strike. Guard capacity is 100. When it reaches zero, guard breaks for 1.35 seconds, blocking is disabled, and the player takes a smaller break-through hit. After guard break, 35% stamina is restored; otherwise stamina regenerates at 24 points per second while block is released.

The guard meter is shown below the health bar. It changes from cyan to amber at low stamina and red when guard breaks.

## Implementation notes

- Player attacks use one reusable `Area2D` and `CollisionShape2D`; each swing tracks enemy instance IDs already hit.
- Enemy bodies are on collision layer 2; the player attack area only scans that layer.
- Enemy AI now telegraphs, executes one strike, and recovers. The strike only connects if the player remains inside its forward attack arc; stepping out of range or behind the enemy avoids it. A parry cancels the attack and enters stagger.
- Combat damage is no longer polled by distance from `main.gd`.
- Touch block is released on button-up, touch-cancel, and application focus loss.

## Verification status

The included Python tests are structural contract checks over the GDScript source. They are not a substitute for Godot's GDScript parser, a headless scene launch, or Android device playtesting. Godot 4.3 and an Android device were not available in the build environment; those checks remain outstanding.
