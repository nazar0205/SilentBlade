# SILENT BLADE v0.3.1 — Technical stabilization

## Changes
- `scripts/enemy.gd`: changed `target` from generic `Node2D` to `SilentBladePlayer`, making `target.crouching` a statically known property.
- `scripts/player.gd`: added `release_controls()` to clear transient touch/control state after application focus loss.
- `scripts/virtual_joystick.gd`: added `cancel_input()` to release its active touch and emit a zero axis value.
- `scripts/main.gd`: added focus-loss handling; releases all virtual actions, resets joystick input, and clears player transient controls.
- `.github/workflows/godot-validation.yml`: added Godot 4.3 CI import/parser and main-scene smoke-launch jobs; logs are uploaded as an artifact.

## Verification not performed

Therefore no Godot 4.3 import, GDScript compiler/parser, scene load, runtime gameplay, Android multitouch, Android export, or APK test is claimed. The GitHub Actions workflow must be pushed to a GitHub repository and run before those checks have real results.

## GitHub Actions from Android
1. Upload/push the complete project folder contents to a GitHub repository (the `.github/workflows/godot-validation.yml` file must be included).
2. Open the repository in the GitHub mobile app or browser.
3. Open **Actions**.
4. Select **Godot project validation**.
5. For a manual run, choose **Run workflow** and confirm the branch.
6. Open the run and inspect the `validate` job. A green check means the CI commands exited successfully.
7. Open **Artifacts** and download `silent-blade-godot-validation` to inspect the logs.

A green CI run verifies import/parser and a short headless scene launch in the CI container. It does not verify touch controls on a physical Android phone or produce an APK.
