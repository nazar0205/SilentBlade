# SILENT BLADE v0.5 — Advanced Movement System

This update extends the existing Godot 4.3 project. It preserves the v0.4.1 combat scripts and the current scene/HUD/menu structure.

## Jump model

- `MAX_JUMPS = 2`: one ground/coyote jump and one airborne jump.
- `COYOTE_TIME = 0.12`: refreshed while grounded and counted down after leaving a ledge. It is consumed by the first jump.
- `JUMP_BUFFER_TIME = 0.15`: a press made shortly before landing is retained and consumed as soon as the floor contact is confirmed.
- The jump count resets only while the character is grounded and not already moving upward. This avoids a stale `is_on_floor()` result resetting a buffered takeoff on the next physics tick.
- Releasing jump while rising scales vertical velocity by `JUMP_CUT_MULTIPLIER = 0.48`. Holding jump for up to `JUMP_HOLD_DURATION = 0.22` applies `JUMP_HOLD_GRAVITY_SCALE = 0.62`, producing a higher arc.
- The second jump has its own short cyan ring/side-burst visual response.

## Grapple and swing physics

The existing anchor list, selected grapple point, rope rendering, and toggle control are retained.

1. Candidate anchors are filtered by range and facing direction.
2. Before attaching, `_has_clear_grapple_line()` queries the 2D physics space from the player toward the anchor. The query uses collision layer mask 1 (the current solid world/platform layer) and excludes the player RID. An obstructed anchor is rejected.
3. Rope length is initialized to the measured current distance, with a minimum slack length of 90 px. The old `distance * 0.82` shortening has been removed, so attaching does not pull/snap the character toward an anchor.
4. Gravity continues to act while attached. Horizontal input applies a tangent acceleration (`GRAPPLE_PUMP_ACCEL = 560`) instead of replacing horizontal velocity, so momentum carries through the arc and can be pumped by the player.
5. After `move_and_slide()`, excess rope length is corrected with a small `move_and_collide()` motion toward the pivot. This retains collision handling against the level geometry; the player position is never assigned directly to the rope circle.
6. The radial outward velocity component is removed only while the rope is taut. Tangential velocity is retained.
7. Line of sight is checked again during the swing. If a wall/platform blocks the line, the grapple detaches without zeroing velocity.
8. Releasing/toggling the grapple detaches without changing the current velocity. Starting dash or jumping while attached also detaches first and retains horizontal swing momentum.

The rope physics assumes solid level geometry uses Godot collision layer 1. Any future grappling-blocking geometry must also be assigned to that layer or the ray mask must be expanded.

## Dash

- Duration: `0.20 s`; cooldown: `0.82 s`.
- Horizontal speed is eased from the current velocity to the dash target over `0.065 s`, then held until the timer ends.
- On completion the player receives `420 px/s` exit speed. A short `0.22 s` lower-drag window lets some momentum carry into ordinary movement.
- Dash detaches the grapple without deleting current velocity, chooses the current movement direction when present (otherwise facing), and remains blocked while guarding or during guard break/death.
- Movement continues through `CharacterBody2D.move_and_slide()`, so ordinary body collisions still resolve the dash against walls and platforms.

## Android input

The virtual joystick and independent action buttons remain in place. The jump button still maps button-down/button-up to `Input.action_press/release`, so holding it controls jump height and repeated taps trigger the second jump. The grapple button remains a toggle: tap to attach, tap again to release. Dash remains a separate button and can be tapped while moving with the joystick.

A canceled screen touch now invokes the common input reset, releasing movement, jump, crouch, dash, grapple, attack and block; the virtual joystick is canceled and the player's transient controls are cleared. Window/application focus loss uses the same reset path.

## Preserved v0.4.1 systems

No changes were made to the enemy profiles, enemy state machine, player attack profiles/hitbox registration, block/parry/stamina logic, enemy damage/death handling, HUD layout, camera, title screen, pause panel, mission results or replay flow. Existing combat contract tests remain in the suite.

## Verification boundary

Static source-contract tests cover the movement timings/state transitions, physical grapple constraint and ray query, velocity-preserving detach, dash/cooldown gate, touch cancellation and v0.4.1 regression wiring. They do not simulate Godot physics. Runtime swing stability, wall contacts, precise jump curves, Android multitouch and physical-device behavior require the Godot 4.3 editor/headless runner and an Android device.
